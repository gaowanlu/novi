玩家发的消息 本地直接加密再发送消息 先写入db 统一塞入 Kafka 消费者消费 为消息的接受者写一份消息 后进行写入确认再写去Kafka 消费时将玩家消息标记为已经送到目标用户 然后向目标用户推送已送达状态
Kafka消费者收到有接受者新的消息写入db后，通知websocket让玩家主动的去请求服务器拉去自己新的消息 送服务器拉到的消息需要进行本地解密 然后向服务器发送确认已读消息
这样基本上用户之间完成了事实通信，虽有延迟但肯定能接受 可以慢慢优化
用户鉴权 用jwt 服务器直接读redis,可以先不用websocket先用http的长连接 定时请求服务器自己是否有新的消息需要拉取，这些肯定是可以慢慢优化的，建议从一开始就直接用websocket
